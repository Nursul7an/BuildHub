# Build Hub — реализация прототипа

Рабочее приложение по макету `project/Прототип - всё приложение.dc.html` из Claude Design.
Пять ролей, 64 экрана, живые данные: действие одной роли видно другой.

## Запуск

```bash
npm install
npm run seed            # база SQLite с данными прототипа
npm run dev             # API на :4000 и веб на :5173
```

Открыть http://localhost:5173. Пароль всех демо-учёток — `buildhub2026`,

## Устройство

```
packages/shared   роли, матрица прав, доменные типы, контракты API
apps/server       Fastify + Prisma (SQLite), JWT, правила предметной области
apps/web          Vite + React + TS, экраны по ролям
scripts           проверка: обход всех экранов и главный путь в браузере
```

Сев сдвигает даты так, чтобы сценарий прототипа (понедельник 4 августа)
приходился на день запуска: армирование просрочено на 2 дня, заявка висит
у снабжения 2 дня, отчёт за вчера возвращён ПТО.

## Что живёт на сервере, а не в интерфейсе

Прототип рисует замки и причины блокировок. Здесь это ограничения, которые
клиент обойти не может:

| Правило | Где |
|---|---|
| Минимум одно фото в записи отчёта | `rules.ts · checkReportEntry` |
| Метод зимнего бетонирования при t воздуха ниже +5 °C | там же |
| Предъявление к освидетельствованию только при 100% | `rules.ts · checkCanPresent` |
| Извещение не позднее чем за 3 рабочих дня | `rules.ts · isValidPresentationDate` |
| Процесс после требующего АОСР стоит, пока акт не подписан | `rules.ts · recomputeChainBlocks` |
| Распалубка закрыта, пока не набрана прочность бетона | `rules.ts · checkStrengthGate` |
| Заявка на технику не уходит с неготовым фронтом | `rules.ts · checkFrontChecklist` |
| Выдача сверх норматива требует причины | `routes/materials.ts` |
| Сумма выше лимита автономности уходит директору | `rules.ts · needsEscalation` |
| Приёмка недоступна, пока груз в пути | `routes/zayavki.ts` |
| Права роли — фильтр до выборки, а не после | `auth.ts · requirePermission` |

## AI-помощник

По ТЗ модель не считает и не решает, кому что показывать. Помощник — набор
структурных запросов: числа берутся из базы, фильтр по правам роли стоит на
уровне данных, к каждому ответу прилагается источник и действия. На вопрос вне
своих прав или вне шаблонов отвечает честным «не могу ответить», а не догадкой.

## Проверка

```bash
npm run verify          # открыть все 64 экрана + прокликать главный путь
npm run verify:screens  # только обход экранов
npm run verify:flow     # только главный путь
npm run typecheck
```

`verify:flow` проходит сценарий в браузере через три роли: прораб фиксирует
нехватку материала → заявка уходит в снабжение и попадает в реестр; прораб
сдаёт дневной отчёт → он появляется в очереди ПТО; корректировка ПТО требует
причины; простой с ценой оказывается в ленте руководства.

Для запуска нужен Chromium. Если он не в системном пути, укажите его:
`CHROMIUM_PATH=/путь/к/chrome npm run verify`.

## Расхождения с прототипом

- **Фото** заводятся заглушкой с геометкой и временем: камеры в вебе нет,
  а сама метка в модели данных есть и проверяется.
- **Голосовой ввод** нарисован кнопкой, распознавание не подключено.
- **Режим планёрки** сделан экраном приложения, а не отдельной десктоп-версткой.
- **Объёмы армирования** хранятся в тоннах (в прототипе те же величины были
  подписаны килограммами при значении 7 100).
